前鹅厂王津银：FDE 在中国，到底成立吗？

| Comments

一位做了十年软件、又被自己反复否掉的老板，把这一年的转型路径拆成了七层。前半场在讲他否掉了什么，后半场在讲他重构成了什么。

01 他先否掉了一个词：拼接怪胎

传统信息系统是什么？是地面上的固定导航路径——写操作文档，告诉员工第一步第二步第三步怎么用。

智能系统是什么？是空中的路线，不确定、随场景变化。

他说，你非要把这两种模式焊在一起，等于把无人机架在皮卡车的后备箱里，我管它叫 freak，拼接怪胎。

从原理上讲，一个是执行的确定性系统，一个是随机决策系统，这两个是不兼容的。
录屏 00:28–00:37

更关键的是第二句：今天传统软件系统能拿到的，是一个碎片化的上下文，这个上下文不足以支撑 AI 做出智能的表达。他把这称为核心问题。

所以有了那个界定，他后来还专门传递给客户：

「今天你不要把 AI 当成技术工具来看了。它其实是在复制你整个公司、整个团队的智力能力，把智力要素复制出来——这是一种新质生产力。」

这句话是全场的地基。后面所有的报价、客户选择、交付方式，都是从这个地基上长出来的。

02 FDE 在中国成立吗 先回答三个问题

他几乎很少提 FDE 这个词，也承认这是个外来品、是从 Palantir 长出来的东西。所以每次被问「中国的 FDE 成立吗」，他的反问是：

一、你的商业模式是什么

如果你还在延续过去的软件项目逻辑，那就是用过去的确定性思维去签一个 AI 的项目，大概率你是结不了项目的。他说这是大部分 FDE / AI 项目收不了尾的核心原因——他就在某个 FDE 群里看到过这种典型问题。

二、你的客户是谁

如果客户还是以前那种软件外包客户、买人头的客户，今天支撑不了你。而且客户的流程机制本身就长成那个样子，不会为 AI 服务模式改。

他现在的 AI 业务按人月报价，坚决不签 361、334 这种分期合同："这种合同一旦签了，接下来你的 AI 业务是没完没了的。"

银行、运营商、电力，这些他过去软件业务的老客户，现在几乎不碰。因为它们的流程一定会让你做 POC、写技术参数、三家必选。而 POC 的代价是：

  • 你把东西全给他们看了——"脱裤了之后"，他们自己要复刻其实非常容易
  • 或者你自己不复刻，但另外一家服务商拿到了你的方案，用 AI 复刻一个出来也很快
  • "我们必须承认，今天在技术这个维度上，很多东西平权了"

技术平权之后，商业路径里的核心竞争力到底是什么？这是他留给自己、也留给听众的问题。

三、重流程的生意适合 AI 吗

一个项目靠六到九个月中标，签合同，拿 30% 首款，再进场干几个月——那时候技术参数可能都变了。

他举了一个很扎的例子："今年 11 月初，扣扣是下线。" AI 时代一个产品的生命周期，有可能非常短暂。

而他现在是：产品两天发一个版本，软件功能不收费，需求随便提，觉得 OK 就做，顶多一两天交付。

你选择去服务他们，就意味着你只能用那个模式和甲方的流程、机制去匹配。那就意味着 FDE 是不成立的。
关于「FDE 不就是新型人力外包吗」的回应

他甚至把那个悖论说穿了：客户有人力成本限价，比如一个人月不能超过 3.68 万。"我自认为我在 AI 上面很牛逼，但我依然只能 3.68 万卖给客户。"——那 FDE 确实只是换了个概念的外包。

03 于是他改了报价， 也改了交付物

这一年他服务了十几家客户，包括几万人的大企业，最后筛出一个百例客户需求池。报价是一个人月大概 18 万。

报这么高，就不能平白无故进场做低价值活动。所以入场前的准备工作在内部全部做完，进场就是实施动作。

「挑你们最难的场景去做。一个月我交付一个成果给你，如果搞不定，我们合作就不合作了。」

这是 8 月底浙江一家企业，老板他从来没见过，在线会上就这么讲的。对方挑了 APS 场景。

一个月里，他到底卖的是什么

  1. 先把认知调过来——你脑子里装的还是信息化、数字化那一套，先得换个坐标系
  2. 把 AI 建构的能力传递给你——能力转移，而不是系统交付
  3. 在一个真实场景里带着你把业务闭环做出来

"我说我能 80% 确定是你想要的。但你要的并不是今天这个 agent skill 本身，我也没拿 agent skill 给你卖多少钱。"

反面例子他也讲得很直白：如果今天交给你一套传统系统，最后你会发现——这个系统怎么维护？未来新功能开发怎么办？这个时候你想撤场都撤不走了。

他把这四项拆开来看：平台坐席费、Token 费、数据面维护费、FDE 陪跑费。这四项是分开列的——陪跑本身被当成一件可以单独计价的东西，而不是打包在系统交付里。

04 七层落地方案框架

这是他今年五六月开始梳理、一直迭代到现在的框架。左侧是价值入口，右侧是用户入口，同一套东西两个方向讲。

录屏截图 · 七层落地方案框架（双向入口）。这一页在整场里反复出现，是他当前的标准讲述结构。

  • 第一层 价值层 · 降本 / 增效 / 提收跟老板只谈这一层，不谈技术、不谈产品、不谈工具
  • 第二层 视角层 · 组织智能 + 业务智能一个讲岗位能力，一个讲业务流
  • 第三层 能力层 · 全面 Agent / Skill 化把岗位经验、知识库变成可被调用的能力
  • 第四层 方法层 · FDE 陪跑方法论方向盘在客户手上，我讲规则、做演示
  • 第五层 承载层 · 人与 AI 的协同工作空间五个统一：任务中心 / Agent Skill / 知识库 / 上下文
  • 第六层 角色层 · 基于角色的专属 AI 工作台把组织里的角色分工用 AI 驱动起来
  • 第七层 入口层 · 极简的人机交互分派一个活出去，一个 bot 接走

他的实战口径很明确：对一个新客户，只讲上面四层就够了。五六七这三层不太跟对方领导讲——讲多了，你自己后面反而没法脱身。

05 价值层：三个词， 六个侧面

跟一号位聊天，不能讲产品逻辑、技术逻辑、工具逻辑——"他根本就听不懂，更不用说了"。要讲一个他听得懂的故事。他从自己当一号位的诉求出发，拆成三个词、每个词两个侧面。

降本，降的是两种成本

  • 资源成本：哪个岗位人太多了，AI 能力导入后资源成本快速收缩。他自己经历过，他服务的客户也都经历过

  • 内部交易成本：人和人之间、岗位和岗位之间的协同代价非常高——开会、拉通、对齐、邮件、电话、每日站会。这些如果交给一条端到端的 AI 工作流去衔接，还需要这么复杂吗？

增效，分两个阶段

  • 个人效率：办公效率提升。这一步有必要——它要让人在认知上真的相信"AI 能帮到我"

  • 组织增效：这一步才是老板真正要的

个人 AI 不等于组织 AI。个人效率提升，不等于组织效率提升。

他给这个判断列了两条原因

原因一，工作流没变。产品经理拿着 Gemini 写需求，设计师用 Figma 生成原型，开发用 Codex 或 Claude Code 做事。可产品经理写完交给 UI/UX，UI/UX 交给研发，研发说搞不定、你改吧，产品经理又回来改——人还在这条流程里控着。各种 AI 能力只是被当成一个技术工具塞进去，流程本身一点没变。

原因二，人性的因素。他在 10 月初让客户做过一次全员调查，普遍反馈是个人 AI 工具能带来 30%~50% 的效率提升。但老板在组织层面感觉不到这个变化——因为人不会把省出来的时间，再拿去抢上面的任务干活，"这几乎是不可能的"。

提收，两点

  • 收入：大部分公司（包括他自己转型时）收入不可能一下子上来，这是硬挑战

  • 利润表质量：从精益思想讲，拒绝浪费本身就是创造利润。今天省下一百万，就是给公司创造一百万的利润

所以这三层六个侧面，整场下来不涉及技术、不涉及产品、不涉及工具——只是"你今天引入 AI 之后，要在这三个维度上看它的效果"。

06 视角层： 其实就是一张二维表

组织平面：把岗位能力全部 Agent / Skill 化

路径是固定的：把岗位经验提取出来 → 把岗位知识库构造出来 → 把 agent skill 写出来 → 把这个能力扩充出去。

扩充之后有两个直接结果：

  • 岗位能力被扩充：以前这个岗位可能就两个人，今天有 agent，相当于差不多十个人
  • 岗位边界被融合：以前销售要找人，现在售前有了 agent，销售是不是可以直接找 agent 去干活？

他还特意把两个常被混用的词分开了：数字员工和 agent 是两个概念，混在一起谈是错的。

业务平面：把老工作流重画一遍

过去研发是一条流水线：产品分析→技术分析→开发→测试→运维部署上线。今天能不能交给一条全新的 AI 驱动工作流去重构它？

那样的话，所谓的 AI pipeline 就是——一个人带着一堆 agent，按一条路径去干活。

两个平面叠起来，就是二维表

横向是岗位，纵向是业务流。他说可以去翻华为的 LTC 流程，它本身就能被转换成一张二维表。而中间交叉的那些格子，就是第三层要做的填空题：岗位 Agent Skill 化。填满之后，整个组织的能力就被全面 Agent / Skill 化了。

07 方法层：Skill 是不值钱的

Agent Skill 是没有价值的，你不要把它当成壁垒的一部分，我也不需要用户为我的 Agent Skill 买单。
他在方法层的第一句话

平台里他自己封装了 task builder、agent builder 这样的套件，让客户快速开发 agent。"这个能力本来就应该转移给你的。"

他年初就在团队内部制止了一件事：不允许 skill 收费。理由很硬——公网 skill hub 里那么多 skill，你真正用了多少？有多少是有价值的？"那里面就是一个 markdown 的文件，不应该形成这种高价值的收费点。"

那陪跑到底是什么

他用了学车的比方：

「今天你来跟我学车，方向盘一定要拿在你手上。学的时候我告诉你交通规则是什么，哪个是刹车、哪个是油门，挂挡怎么挂——适当的我会演示一下。」

陪跑不是顾问。顾问给报告，陪跑是坐在副驾上，随时纠正。而且陪跑的方法要按客户变形：几万人的大型制造业、历史遗留系统极复杂，是一套做法；一个广告公司、一个跨境电商、一个小的外贸公司，又是另一套。但内核不变。

08 承载层： 先给 AI 找到一个家

他抛了一个问题：人有工作空间——规章制度、员工手册、流程，人一进公司就能感知到。那 AI 进来之后，它的工作空间在哪？

这是他去年提炼产品时认为最有特色的一点：AI powered enterprise second workspace，企业智能化的第二工作空间。当时想叫 collaborate space，发现翻成英文不好翻，就保留 workspace 这个概念回来。

他称之为五个统一：统一的 workspace、统一的任务中心、统一的 Agent Skill、统一的知识库、统一的上下文。这是一个包含关系，不是并列。

而且他明确区分了两个词：工作空间不是 project，是"相同语义的上下文"。一个客户就是一个工作空间，里面做了五六个项目，这些项目再基于一套标准规范的目录去分类管理。每个人在自己的位置上看到的，是属于自己的那个语义切片。

目的很实在：锁定权限护栏，并且让 AI 在执行人类任务的时候，越来越准确。

再往上是角色层和入口层

  • 角色层：基于角色打造专属 AI 工作台，把组织里原本人与人之间的分工，用 AI 的方式驱动起来
  • 入口层：人跟 AI 系统的交互要足够的简单。简单到——分派一个活出去，一个 bot 就把它接走了。这件事在企业级环境成立，在上下级分配任务的场景里也成立

录屏截图 · 他自己产品的那一页：成为企业智能化的第二工作空间。注意「第二」这个词——不是替代，是并列再开一个空间。

09 个人 AI 和组织 AI 之间，缺的是秩序

他把这两者的差别讲得很清楚：

  • 个人 AI

公司感知不到。烧的可能是公司的 token，但知识库、上下文都在个人本地处理掉了，没有拿到公司层面。它就只是一个工具。

  • 组织 AI

组织要的是一种秩序。公司的 agent skill 是统一的，岗位的 agent skill 是统一的，知识库是统一的；进到某个项目情境里，上下文也要被统一接上。

如果不能真正建立起组织级的 AI 秩序，我们就又回到工具的逻辑上，让这家公司进入一种耗散的状态。

他判断一家公司 AI 成熟度，只问两个问题

  1. 你们 AI 工具用的是什么？有人说用 Codex，有人说用 DeepSeek，有人说用 Kimi，有人说用 Claude Code——越乱，说明这个组织越乱
  2. 你们 token 用了多少？如果 token 用得不多，甚至一号位根本不知道这个数，那这家公司在 AI 上基本还没开始

他还补了一句刺耳的话：从老板角度，你在某个工具里给自己写了个 skill、让岗位效率提升，这件事已经没有意义了。

10 对一号位怎么讲，以及他不碰的客户

他几乎不跟 CIO / CTO 聊

"一跟他们沟通交流，大部分是失败的，甚至让自己感受不好。"他跟 Workbody 的代理商也聊过这个结论：80~90% 的情况下，CIO / CTO 是企业转型最大的障碍。三个原因：

  1. 他第一反应是用技术视角看：你这系统很简单，我自己可以复刻一个
  2. 他不会把你的方案呈到老板面前，说"我认识了一家代理商，能力很好，能帮到我们"——因为老板会反过来问：你是我们的 CIO，你怎么没想到这一点？
  3. AI 导入到传统 IT 这个生产力部门，最直接的结果就是人员优化和流程重构，尤其 AI coding 是目前最成熟的领域。这一关大部分 CTO / CIO 迈不过去

所以他只跟一号位聊。而跟一号位聊，就不能讲产品、工具、技术——"他也听不懂"。要讲一个他听得懂的故事。

他的开场结构：20 + 5 + 5

  • 20 分钟：讲他对 AI 落地的整套理念，中间一定要把七层框架说清楚——因为客户脑子里装的还是过去信息化、数字化那一套
  • 5 分钟：讲一个案例，另一个客户一个月是怎么达成效果的
  • 5 分钟：把产品讲一下，大概就这么多

两件必须提前讲清楚的事

时间。他始终坚持一个月左右搞定，剩下复制推广客户自己来，他远程支持。因为时间越长、报价越高，客户越不敢投资，"甚至觉得你过来是骗我钱的"。

钱。坐席费用、token 费用（含在套餐里）、数据面的维护费用。必须给客户一个完整的落地保障，这样"降本增效提收、组织智能+业务智能、FDE 陪跑"这套话在时间和成本上才具备可行性。

这两类客户，他建议别碰

有行政属性的客户：政府、行政事业单位、政府监管相关。因为你在挑战的是一整套庞大的制度体系、流程和规范，"这个不是我们今天能碰的"。他说自己从 2015 年出来创业、做了十年多软件，好不容易从那坑里爬出来，"我也不希望各位 FDE 今天又掉到那个坑里去了"。当然如果这个项目就是能赚到钱，那另说。

录屏截图 · 他给团队讲的"洗脑行动 / 一号位带头行动"。这套东西是先在自己公司跑通的，再拿去跟客户讲。

这一年他做得最多的事，是否定

2025 年初公司迷茫时，他做了一次战略研讨会，结论是"我们就不想做项目了"；随后把 EasyOps 的 AI 化停掉，重新做本质洞察、重新设定 AI 产品为什么独立。回头看，走的每一步都 OK，无论对错。

但他最怕的是另一件事：认定一个逻辑，一个季度不变、半年不变、一年不变。时间越长不变，说明这个事情越糟。

所以他把"demo""试点"这些词也换掉了，叫 Spark 项目——不是试点，是星火效应。

还有一个他反复跟团队讲的比喻：满清遗老遗少背后那条长长的辫子，这东西一定要剪，剪的是老的经验、思维模式和认知。

录屏截图 · 他翻出来的脑图：「0 号客户的 25 年重生之路」。上面写着 25 年里多次的自我否定和趋势判断——这套框架是从客户现场长出来的，不是坐着设计出来的。

0 号客户

他把自己当成自己的客户。在优维的转型里，他换了个视角：不把这家公司摘在这场 AI 浪潮之外，"今天优维的 AI 转型不需要第二家公司来服务我，我自己要把自己服务过来"。哪怕他自嘲这是一家"老登公司"。

他给团队分享过的题目一长串：人与 AI 伙伴共生、AI Native 组织转型实践、超级个体、一号位如果重来、打破边界、从报价表看商业模式变化、0 号客户是传递客户价值的源泉……

最后他说，FDE 赚两种钱

一种是信息差的钱，一种是认知差的钱。四线城市里可能还有人不知道 Codex 是什么，这确实是空间。但他提醒：不要赚那种很低级的信息差——比如靠卖 skill 收钱。真正宝贵的是更高维度的认知，和你在客户那里形成的那种"一个月能收很高的费用、客户从上到下都说你们那个 FDE 不错"的结果。

而且这活儿不一定要技术出身：他们公司的第一个陪跑项目是一个有点技术基础的销售去做的，上海一家 800 多人的公司，是他们销售老大去陪跑的。前提只有一个——认知得先建立起来。

一个他用来照镜子的指标

「以前人效是 50 万，今天我做 AI 了，结果一年做下来人效还是 50 万——这个时候你就要反思自己的业务模式了，大概率是出了问题。」

反过来他说，在 AI 时代，做 AI coding 的小伙伴一年做 200 万绝对没问题，因为客户需求太多了。但要用全新的方式去引导他，也切记不要赚快钱。

读后速记 · 整理者提炼，非讲者原话

  1. 报价结构比话术更能决定项目能不能收尾。按月买断、一个月出成果、复制阶段客户自己做——这套结构天然把"没完没了的需求"挡在门外。
  2. 客户筛选是前置动作，不是运气。先判断这个客户的流程会不会为你改变，再决定要不要投入。不改变的客户，技术再强也是消耗。
  3. 卖的是能力的转移，不是系统的交付。系统交付会让你五年都在维护它；能力转移让你一个月就能撤场。
